# 测试用例串行编排页设计

## 背景

当前测试用例页采用左侧用例树、中间流程画布、右侧属性面板的三栏结构。测试步骤本质上是严格按数组顺序执行的串行列表，但页面使用网格背景、开始/结束节点和连接线表达流程，造成了并行编排能力的错误暗示，也压缩了真正需要频繁操作的步骤区域。

本次改造将页面收敛为聚焦双栏编辑器：中间区域快速创建、浏览和排序串行步骤，右侧区域始终编辑当前步骤。用例切换和用例级配置集中到顶部，不再占用常驻左栏。

## 目标

- 让用户能够快速创建、插入、排序、复制、删除和编辑串行测试步骤。
- 最大化中间步骤列表的可用宽度，保证常用信息可扫描且操作稳定。
- 保持右侧检查器只服务当前步骤，避免用例设置和步骤设置混杂。
- 让自动保存状态反映真实持久化结果，而不是仅反映本地组件状态。
- 保持现有 `TestCaseDraft.steps` 数组及执行器顺序语义，不引入数据迁移。
- 同时支持中文和英文界面，并保持现有主题、字体和页面标题规范。

## 非目标

- 不支持并行分支、条件节点、循环、连线或自由画布。
- 不支持多步骤选择、批量编辑或跨用例复制。
- 不在本次改造中重做项目、分组、录制资产或运行记录页面。
- 不改变五种步骤的运行时执行语义。
- 不引入新的用例持久化结构或历史版本系统。

## 选定方案

采用“聚焦双栏”结构：顶部工具栏承载用例上下文和全局操作，主体使用宽幅串行步骤列表加固定宽度步骤检查器。

该方案相比保留左侧用例树，能直接扩大高频操作区域；相比自由画布，它准确表达现有串行数据模型，也能用更低的交互成本支持排序和插入。用例树被替换为顶部选择器，但项目内的全部用例仍可按分组查找和切换。

## 页面结构

### 顶部工具栏

顶部保持应用统一的单层标题栏，不增加描述或小标题。左侧显示页面标题和当前用例选择器，右侧依次显示：

- 用例来源 Tag，例如手工、自然语言、录制或 PRD。
- 运行状态 Tag。
- 自动保存状态；常态不占用持续空间，只在保存中、短暂保存成功或保存失败时显示。
- “用例设置”按钮。
- “添加步骤”主按钮。
- “运行用例”主操作。

用例选择器展示当前项目内的全部用例，并按分组组织。选择其他分组中的用例时，同时同步应用级 `selectedGroupId` 和 `selectedTestCaseId`。用例在设置弹窗中变更分组后，也同步当前分组选择。

### 中间步骤区域

中间区域使用高密度的纵向步骤列表，不显示网格背景、连接线、开始节点或结束节点。每行包含：

- 仅用于拖拽的手柄。
- 连续步骤序号。
- 步骤类型图标和类型名称。
- 步骤标题。
- 单行指令摘要或录制绑定摘要。
- 校验警告。
- 行操作菜单。

选中行使用边框、背景和左侧强调色表达，不使用按钮式 Tag 作为选中容器。步骤标题和摘要截断时提供完整内容的悬停提示。

列表本身独立滚动，底部不保留无意义的大块留白。滚动条位于列表容器边缘，内容区通过内边距避免与滚动条重叠。

### 右侧步骤检查器

右侧保持固定宽度，主体使用 `minmax(0, 1fr)` 获取其余空间。应用最小窗口宽度为 1200px，因此检查器在最小窗口下维持约 320px 至 360px，中间区域获得剩余宽度，不再保留左侧常驻面板。

检查器始终只显示当前步骤属性：

- 所有类型：标题、步骤类型、指令内容。
- 录制回放：额外显示录制资产绑定及资产摘要。
- 其他类型继续使用现有 `title` 和 `body` 字段，不新增运行时字段。

右侧不显示用例名称、URL、分组、环境或备注。上述字段进入顶部“用例设置”弹窗。浏览器会话面板不再嵌在步骤检查器中；浏览器操作仍由录制页和自然语言测试页承担。

## 交互设计

### 初始选择与切换

- 进入用例或切换用例时，默认选中第一步。
- 当前步骤排序后仍保持选中。
- 外部更新导致当前步骤不存在时，选择新的第一步；没有步骤时清空选择。
- 没有用例时展示创建用例空态；用例没有步骤时展示“添加第一步”空态。

### 创建与插入

顶部“添加步骤”默认在列表末尾追加。点击后打开包含五种类型的菜单：动作、断言、提取、录制回放、人工检查。

步骤之间以及列表首尾提供插入位。插入位常态不抢占明显高度，鼠标进入对应间隙后显示“在此插入”；点击后打开同一类型菜单，并在该索引创建步骤。

新步骤创建后：

1. 自动成为当前步骤。
2. 必要时滚动到可见区域。
3. 聚焦右侧标题字段并选中默认标题，允许用户直接输入。

五种步骤的默认值由共享创建函数生成。录制回放步骤沿用当前规则，优先绑定同分组、同环境的默认录制资产；没有可用资产时保持未绑定并显示警告。

### 编辑与自动保存

字段变化立即写入 React 内存状态，保证切换步骤时不丢失输入。持久化层对连续文本输入做约 350ms 的短暂防抖；选择字段、排序、创建、复制和删除等离散操作触发最新状态的保存。

保存反馈使用以下状态：

- `saving`：显示“保存中”。
- `saved`：成功后短暂显示“已保存”，随后回到无提示常态。
- `error`：显示“保存失败”和重试操作，直到最新状态保存成功。

保存请求使用递增版本标识，只允许最新请求更新展示状态，避免较早请求晚返回时覆盖较新的结果。失败不会回滚内存中的编辑内容；重试始终保存最新完整状态。

### 排序

拖拽只能从手柄开始，点击行的其他区域只负责选择步骤。拖动过程中显示当前行的拖动态和目标索引处的清晰插入线。

放置成功后一次性更新 `steps` 数组；拖拽取消、落回原位或落点无效时不产生数据修改。行菜单提供“上移”和“下移”，既用于精确调整，也作为不依赖拖拽的可访问操作。首行禁用上移，末行禁用下移。

### 复制与删除

“复制”生成新的步骤 ID，将副本插入原步骤之后，并自动选中副本。副本保留步骤类型、标题、指令和录制绑定。

“删除”需要二次确认。删除当前步骤后优先选择原位置的下一步；没有下一步时选择前一步；列表变空时进入空态。取消确认不修改数据和选择状态。

### 用例设置

“用例设置”打开现有设计系统风格的 Dialog，编辑用例名称、目标 URL、分组、环境和备注。字段沿用自动保存语义，不增加底部“保存”按钮；关闭弹窗不会丢失已经进入内存状态的内容。

### 运行与校验

以下情况视为步骤配置不完整：

- 标题为空或只有空白字符。
- 动作、断言、提取或人工检查的指令为空。
- 录制回放没有绑定仍存在的录制资产。

配置不完整时，步骤行显示警告，右侧对应字段显示错误状态，并禁用“运行用例”。运行按钮的悬停提示说明首个阻塞原因。用例没有步骤时同样禁止运行。

校验只用于编辑反馈和运行门禁，不修改持久化数据，也不改变现有运行器对有效步骤的执行方式。

## 组件边界

`TestCaseManagementPage` 保持页面容器职责，负责连接应用状态和页面级临时状态。页面内按以下职责拆分小组件，优先与页面同文件组织，只有基础菜单原语进入 `src/components/ui`：

- `CaseEditorToolbar`：用例选择、状态、用例设置、新增和运行。
- `SerialStepList`：列表空态、插入位、拖拽状态和滚动容器。
- `SerialStepRow`：单行展示、选择、手柄、校验和行菜单。
- `StepTypeMenu`：统一提供五种新增类型。
- `StepInspector`：按当前类型编辑步骤字段。
- `CaseSettingsDialog`：编辑用例级字段。

类型菜单和行菜单使用统一的 Radix/shadcn Dropdown Menu 原语；设置使用仓库现有 Dialog。不会为本页创建独立组件目录或页面专属设计系统。

## 数据操作与契约

`TestCaseDraft.steps` 仍是步骤顺序的唯一事实来源。共享模型层提供可独立测试的纯操作：

- 创建五种类型的默认步骤。
- 在指定索引插入步骤。
- 将步骤移动到指定索引。
- 使用新 ID 复制步骤并插入原步骤之后。
- 删除步骤。
- 计算步骤级校验结果和首个运行阻塞原因。

页面与 `App` 的交互契约需要支持：

- 选择用例时同步对应分组。
- 创建或复制步骤后返回新步骤 ID。
- 按 ID 和目标索引移动步骤。
- 删除或更新当前步骤。
- 接收真实持久化状态并触发重试。

`App` 继续拥有项目和用例数据。页面只拥有 `selectedStepId`、拖拽源与目标、当前插入位置、菜单/弹窗开关和待聚焦步骤 ID，不复制完整用例或步骤集合。

## 数据流

1. `App` 根据当前项目、分组和用例 ID 解析 `selectedTestCase`，并传入页面。
2. 页面根据 `selectedStepId` 从 `selectedTestCase.steps` 派生当前步骤。
3. 编辑、插入、排序、复制或删除操作调用应用层回调，最终以纯数组变换更新当前用例。
4. `projects` 更新后，应用层构造最新 `StudioState`，按自动保存规则调用 `saveStudioState()`。
5. 持久化 Promise 的最新结果更新保存状态；页面只展示状态，不自行访问 Electron 或 `localStorage`。
6. 运行时继续接收完整用例，并按 `steps` 数组顺序执行，不需要适配新的数据结构。

## 异常与边界状态

- 无项目：沿用页面级无项目空态，不渲染失效工具栏。
- 无用例：提供创建用例入口，不显示空检查器。
- 无步骤：提供添加第一步入口，运行按钮禁用。
- 录制资产被删除：绑定失效步骤显示警告，并阻止运行直到重新绑定。
- 当前步骤被外部删除：自动选择新的第一步，不保留悬空 ID。
- 拖拽中数据发生变化：按步骤 ID 重新解析源和目标；任一不存在则放弃移动。
- 持久化失败：保留最新内存状态，显示错误和重试，不伪装成已保存。
- 保存请求乱序：只有最新版本请求可更新最终状态。

## 测试策略

### 共享模型测试

在 `shared/studio.test.ts` 覆盖：

- 五种步骤的默认值和唯一 ID。
- 列表首部、中间和尾部插入。
- 向前、向后、原位和无效目标移动。
- 复制后的位置、内容和新 ID。
- 删除存在或不存在的步骤。
- 各步骤类型的校验结果。

### 页面组件测试

在 `TestCaseManagementPage.test.tsx` 覆盖：

- 进入和切换用例默认选中第一步。
- 顶部追加和步骤间插入打开相同类型菜单。
- 创建与复制后选中新步骤并聚焦标题。
- 只有手柄能够开始拖拽，落点插入线对应正确索引。
- 上移、下移、复制和删除的边界行为。
- 删除确认、取消和删除后的邻近选择。
- 五种步骤的检查器字段和录制绑定警告。
- 用例设置弹窗不与步骤检查器混用。
- 空列表、无用例、无项目和配置不完整状态。
- 中文、英文文案及关键可访问名称。

### 应用与持久化测试

在 `src/App.test.tsx` 或持久化边界测试中覆盖：

- 跨分组选择用例时同步分组 ID。
- 连续输入只以最新完整状态完成保存。
- 保存状态按 `saving -> saved` 变化。
- 失败后保留编辑内容并可重试。
- 乱序 Promise 不覆盖最新保存状态。

### 回归验证

- 保留并更新现有运行器顺序测试，确认执行顺序与 `steps` 数组一致。
- 运行聚焦测试、完整 Vitest 套件、生产构建和 `git diff --check`。
- 在 1200x760 最小窗口及更大桌面窗口验证列表可用宽度、独立滚动、插入线、菜单、Dialog、亮暗主题和中英文文本。

## 验收标准

- 页面不再显示左侧常驻用例树、网格背景、连接线和开始/结束节点。
- 当前项目的用例可从顶部选择器切换，跨分组选择保持全局选择状态一致。
- 中间区域能追加或在任意间隙插入五种步骤，并在创建后直接进入标题编辑。
- 拖拽只由手柄触发，列表顺序和运行顺序始终一致。
- 行菜单完整支持上移、下移、复制和带确认的删除。
- 右侧只显示当前步骤属性；用例级字段统一进入设置弹窗。
- 自动保存反馈来自真实持久化结果，失败时内容不丢失且可以重试。
- 配置不完整的步骤有明确反馈，并且不能启动运行。
- 旧用例无需迁移即可继续编辑和执行。
- 页面在最小应用窗口、亮暗主题和中英文环境下无内容重叠或不可达操作。
