# 产品需求与范围

## 1. 产品定位

PlayTest Pro 是一个本地桌面自动化测试 Agent。

它帮助用户通过自然语言、用户操作录制或 PRD/PDF 文档生成测试路径，并由 Agent 控制浏览器执行、观察页面状态、判断测试结果、沉淀测试资产。

它的核心不是“脚本编辑器”，也不是“测试管理表单系统”，而是一个围绕 Web UI 测试闭环运行的智能工作台：

- 理解测试目标
- 规划测试步骤
- 操作受控浏览器
- 采集截图、DOM、日志和 trace
- 判断通过或失败
- 生成运行记录和失败归因
- 将有效路径沉淀为用例、录制资产和报告

## 2. 目标用户

核心用户：

- 测试工程师：希望快速构建、维护和回放 UI 自动化测试。
- 开发工程师：希望用自然语言快速完成回归验证。
- 产品经理 / QA 分析人员：希望从 PRD 或验收标准直接生成测试路径。
- 数据/运营后台负责人：需要对图表、表格、筛选器和复杂管理后台做稳定巡检。

## 3. 核心价值

- 降低门槛：用户可以先描述目标或录制路径，而不是先写 Playwright 脚本。
- 智能执行：Agent 能根据页面状态规划、执行、观察和校验。
- 工程沉淀：探索式测试可以沉淀为可维护用例、录制资产和运行记录。
- 本地可控：浏览器、密钥、项目配置和运行产物优先保存在本地。
- 面向真实业务页面：重点适配图表、表格、筛选器和后台管理系统。

## 4. 产品信息架构

### 4.1 应用级结构

- 启动屏
- 工作台首页
- 项目管理
- PRD 分析
- 测试用例
- 运行记录
- 自然语言测试
- 流程编排
- 录制回放
- 设置弹窗

### 4.2 启动屏

首次加载应用时显示独立启动屏。

职责：

- 引导用户配置 Midscene。
- 允许用户跳过配置。
- 跳过或配置完成后，后续加载不再自动显示。
- 若后续进入依赖 Midscene 的功能但未配置，则打开设置弹窗并定位到 Midscene 配置项。

### 4.3 首页

首页是 Agent 总览，不是复杂编辑页。

职责：

- 展示项目质量概览。
- 展示测试资产统计。
- 展示最近执行结果。
- 提供核心 Agent 功能入口。

### 4.4 项目与分组

项目是一级管理维度，分组是项目内二级管理维度。

项目需要支持：

- 新增、编辑、删除
- 应用 URL
- 环境配置
- 浏览器配置
- 登录凭证引用
- 默认上下文

分组需要支持：

- 新增、编辑、删除
- 按模块、页面、业务域组织测试资产
- 用例、录制和 PRD 路径按分组归属

### 4.5 自然语言测试

自然语言测试是即时 Agent 执行入口。

用户目标：

- 输入一句测试目标。
- Agent 操作浏览器执行。
- 系统返回步骤日志、截图和判断结果。
- 用户可以把有效步骤保存为用例。

### 4.6 录制回放

录制回放是用户路径采集入口。

用户目标：

- 在受控浏览器中操作应用。
- 系统记录导航、点击、输入、等待、断言和截图。
- 回放录制路径并对比关键页面状态。
- 将录制路径转为正式测试用例。

### 4.7 PRD 分析

PRD 分析是测试路径生成入口。

用户目标：

- 上传 PDF、Markdown 或文本 PRD。
- 系统提取功能点、验收标准、状态变化和边界条件。
- Agent 生成测试路径和优先级。
- 用户可以一键生成用例或录制草稿。

### 4.8 运行记录

运行记录是 Agent 结果中心。

用户目标：

- 查看每次 Agent 执行结果。
- 查看步骤、截图、日志、trace 和失败原因。
- 按项目、分组、用例、环境过滤。
- 对失败结果进行复跑或沉淀修复建议。

## 5. Midscene 配置规则

Midscene 是自然语言执行、语义定位和视觉判断的关键引擎。

必填配置：

- `MIDSCENE_MODEL_BASE_URL`
- `MIDSCENE_MODEL_API_KEY`
- `MIDSCENE_MODEL_NAME`
- `MIDSCENE_MODEL_FAMILY`

可选配置：

- `MIDSCENE_PREFERRED_LANGUAGE`
- `MIDSCENE_REPLANNING_CYCLE_LIMIT`
- `MIDSCENE_OPENAI_HTTP_PROXY`
- 项目默认上下文

拦截规则：

- 首次加载应用时显示启动屏，可配置或跳过。
- 启动屏配置完成或跳过后，后续加载不再显示启动屏。
- 用户进入自然语言、流程编排、录制回放等依赖 Midscene 的功能时，如果配置不完整，则弹出设置弹窗并默认选中 Midscene 栏目。

## 6. MVP Agent 范围

### 6.1 必须支持

- 独立启动屏和 Midscene 配置引导。
- 项目、分组、环境、用例、录制、PRD、运行记录的本地管理。
- 受控浏览器会话启动。
- 自然语言输入触发 Agent 执行。
- Agent 执行过程产生结构化步骤日志。
- 每次执行保存运行记录。
- 失败时保存截图和错误原因。
- 录制资产可以回放并生成用例。

### 6.2 推荐支持

- PRD/PDF 生成测试路径。
- 运行记录支持截图、trace 和日志入口。
- 图表与表格页面的常见断言模板。
- 失败结果的 AI 归因和修复建议。
- 将自然语言探索结果保存为用例步骤。

### 6.3 暂不优先

- 云端同步。
- 多人协作。
- 权限模型。
- 大规模 CI 调度。
- 移动端自动化。
- 跨浏览器云真机矩阵。

## 7. 典型用户流程

### 场景 A：首次启动

1. 用户打开客户端。
2. 看到独立启动屏。
3. 用户配置 Midscene 或选择跳过。
4. 系统进入工作台。
5. 后续加载不再自动显示启动屏。

### 场景 B：自然语言 Agent 执行

1. 用户选择项目和环境。
2. 进入自然语言测试。
3. 输入“登录后台，筛选近 30 天数据，并验证图表和表格都刷新”。
4. Agent 规划步骤。
5. Executor 控制浏览器执行。
6. Observer 采集截图和页面状态。
7. Verifier 判断结果。
8. Reporter 写入运行记录。

### 场景 C：录制路径转回放用例

1. 用户进入录制回放。
2. 启动受控浏览器。
3. 操作页面完成一条业务路径。
4. 系统记录时间线。
5. 用户生成回放用例。
6. 后续可以执行该用例并对比关键节点。

### 场景 D：PRD 生成测试路径

1. 用户上传 PRD/PDF。
2. 系统抽取需求内容。
3. Agent 生成测试路径和优先级。
4. 用户选择路径生成用例或录制草稿。
5. 执行结果回写运行记录。

## 8. 非功能要求

### 8.1 可解释性

- Agent 每一步都必须有可读日志。
- 失败必须定位到具体步骤。
- 关键步骤应保存截图或 trace。

### 8.2 可维护性

- 自动生成的用例必须可编辑。
- 录制资产必须可查看、重命名、分组和删除。
- PRD 生成路径必须可人工确认后落库。

### 8.3 安全性

- API Key 不应直接暴露给普通 UI 逻辑。
- Renderer 只通过受控 IPC 使用主进程能力。
- 浏览器执行、文件读写和模型调用应由主进程 runtime 承担。

### 8.4 稳定性

- 浏览器操作需要等待策略、重试策略和超时策略。
- 对动态页面需要语义定位和 fallback selector。
- 运行失败也必须保存可诊断结果。

## 9. MVP 验收标准

- 首次启动显示独立启动屏。
- 跳过或配置完成后，后续加载不再自动显示启动屏。
- Midscene 未配置时，依赖功能会打开设置弹窗并定位到 Midscene。
- 用户可以发起一次自然语言测试目标。
- 系统可以启动受控浏览器并执行至少一个真实页面动作。
- 执行结果会进入运行记录。
- 失败时可以看到失败步骤和截图。
- 录制资产可以生成回放用例。
