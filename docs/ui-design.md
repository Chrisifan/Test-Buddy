# UI 设计

## 1. 设计目标

UI 的最终目标是承载自动化测试 Agent，而不是普通管理后台。

界面需要让用户始终知道三件事：

- 我现在要让 Agent 做什么。
- Agent 正在执行到哪一步。
- Agent 得出了什么结论，以及证据在哪里。

设计关键词：

- 工作台感
- 高信息密度但低噪音
- 少边框、少嵌套
- 明确的执行状态
- 图表/表格测试友好
- 亮色和暗色主题一致

## 2. Agent 闭环对应 UI

```text
Intent 输入
  ├─ 自然语言输入
  ├─ 录制操作路径
  └─ PRD/PDF 上传

Plan 计划
  ├─ 测试路径
  ├─ 用例步骤
  └─ 风险与优先级

Execute 执行
  ├─ 受控浏览器
  ├─ 步骤进度
  └─ 实时日志

Observe 观察
  ├─ 截图
  ├─ DOM 摘要
  ├─ URL / 标题
  └─ console / network 信号

Verify 判断
  ├─ 断言结果
  ├─ 图表/表格检查
  └─ 失败原因

Report 沉淀
  ├─ 运行记录
  ├─ 失败归因
  └─ 可复用测试资产
```

## 3. 信息架构

```text
Startup Page
  ├─ Midscene 快速配置
  ├─ 跳过入口
  └─ Agent 能力说明

Workbench Shell
  ├─ Sidebar
  ├─ Topbar
  └─ Content Area

Pages
  ├─ 首页 / Agent 总览
  ├─ 项目管理
  ├─ PRD 分析
  ├─ 测试用例
  ├─ 运行记录
  ├─ 自然语言测试
  ├─ 流程编排
  └─ 录制回放

Settings Modal
  ├─ 外观
  ├─ Midscene
  ├─ Runtime
  └─ Network
```

## 4. 启动屏

启动屏是独立页面，不属于首页空态。

展示时机：

- 应用首次加载。
- `startupGuide.completed` 为 `false`。

隐藏规则：

- 用户点击跳过。
- 用户完成 Midscene 必填配置并进入工作台。

设计要求：

- 有步骤条。
- 有 Midscene 快速配置。
- 说明跳过后的影响。
- 不出现左侧菜单和顶部工作台栏。
- 文案使用中文。

## 5. 首页 / Agent 总览

首页是统计与入口页面。

首页的数据范围是整个应用工作区，不随当前项目切换而变化。项目选择只服务于项目级配置和测试操作页面。

适合展示：

- 全部项目的质量状态。
- 最近 Agent 执行结果。
- 测试资产数量。
- 失败风险。
- 核心入口。

不适合展示：

- 大量表单。
- 多层卡片。
- 长日志。
- 复杂编辑器。

首页应该一屏展示尽可能多的统计信息，但不要通过堆叠边框实现密度。

## 6. 功能页面原则

功能页面要尽量精简，减少冗余容器。

统一结构：

- 固定高度的单层页面标题区，不展示 eyebrow 或描述。
- 标题左对齐；状态以 Tag 形式、操作按钮置于标题同行右侧。
- 内容区域独立滚动。
- 标题不随内容滚动。
- 不使用异常吸顶效果。
- 页面标题字号、间距和操作区保持一致。

## 7. 自然语言测试页

页面目标：

- 输入 Agent 测试目标。
- 观察执行计划和执行日志。
- 查看浏览器状态和截图。
- 保存有效步骤。

布局建议：

- 左侧：输入、模式、环境、发送按钮。
- 中间：Agent 执行流。
- 右侧：浏览器状态、上下文、最近结果。

关键状态：

- 未配置 Midscene。
- 浏览器未启动。
- Agent planning。
- Agent executing。
- Agent verifying。
- passed / failed。

## 8. 录制回放页

页面目标：

- 采集真实用户路径。
- 展示录制时间线。
- 回放和对比关键节点。
- 转成测试用例。

布局建议：

- 左侧：录制资产列表。
- 中间：浏览器/录制舞台。
- 右侧：时间线、元信息、转用例操作。

## 9. PRD 分析页

页面目标：

- 上传文档。
- 展示需求摘要。
- 展示生成的测试路径。
- 支持路径转用例或录制草稿。

布局建议：

- 左侧：文档列表和上传。
- 中间：文档摘要和覆盖区域。
- 右侧：生成路径和操作按钮。

## 10. 运行记录页

页面目标：

- 做 Agent 执行结果中心。

展示内容：

- Run summary。
- Step logs。
- Screenshots。
- Trace / report artifacts。
- Failure reason。
- Rerun entry。

统计页面要提高信息密度；详情页面要强调证据链。

## 11. 设置弹窗

设置弹窗是配置中心和功能门禁入口。

要求：

- 左侧栏目与右侧内容联动。
- 从 Midscene 依赖功能触发时，默认选中 Midscene。
- Midscene 必填项未完成时保存按钮不可用。
- 输入框宽度不应盲目拉满，需要按字段类型控制。
- 弹窗必须明显区别于背景。

## 12. 视觉语言

方向：

- 科技工作台。
- 明亮主题以白色为主。
- 暗色主题以深色工作台为主。
- 主色用于状态、进度和关键 CTA。
- 减少边框，用背景层级、留白、字号和图标建立结构。

组件原则：

- 卡片少层级。
- 表单区域紧凑。
- 操作按钮靠近上下文。
- 统计卡片允许高密度。
- 功能页面减少装饰。

## 13. 动效原则

动效服务状态变化，不做装饰噪音。

适合使用：

- 页面进入淡入和轻位移。
- 内容块分组进入。
- Agent 步骤执行状态变化。
- 录制事件写入时间线。
- 运行结果完成反馈。

不适合使用：

- 大面积循环动画。
- 每个卡片都有复杂 hover。
- 影响阅读的吸顶和遮挡效果。

## 14. 设计验收标准

- 首次加载看到独立启动屏。
- 工作台主体统一，不出现首页与功能页割裂。
- 统计页一屏能看到较多信息。
- 功能页尽可能精简。
- 页面标题样式一致。
- 不出现多层卡片堆叠。
- Midscene 未配置时的门禁清晰。
- Agent 执行过程、结果和证据链清晰可见。
