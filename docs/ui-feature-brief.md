# PlayTest 已实现功能描述文档（供 UI 设计使用）

## 1. 产品定位

PlayTest 是一个面向网页应用的自动化测试工作台，核心目标是让测试人员、产品人员或研发人员通过三种方式沉淀测试资产：

1. 用自然语言直接操作、断言和提取页面信息。
2. 在受控浏览器中录制用户真实操作路径，并将录制结果作为回放依据。
3. 导入 PRD、Markdown、文本或文字型 PDF，自动分析需求并生成测试路径草案。

当前应用主要服务图表展示、表格展示、筛选查询、登录态验证、路径回归和结果分析等网页应用测试场景。产品以“项目”为顶层工作空间，项目内包含环境、分组、测试用例、录制资产、PRD 文档和运行记录。

## 2. 当前信息架构

应用采用左侧工作台导航，主体区域按功能页切换。当前已实现页面如下：

| 页面 | 作用 | 主要用户任务 |
| --- | --- | --- |
| 首页 / 统计数据 | 汇总项目质量、覆盖、运行、资产和风险信号 | 快速判断当前项目健康度，进入下一步工作 |
| 项目控制台 | 管理项目、分组、环境和登录凭据 | 创建项目、维护环境 URL、维护二级分组、保存账号信息 |
| 需求文档分析 | 导入 PRD 并生成测试路径草案 | 上传/粘贴需求，生成用例或录制草稿 |
| 用例工作台 | 管理测试用例和步骤编排 | 编辑测试路径，绑定录制资产，执行用例 |
| 运行记录 | 查看执行结果和质量分析 | 按项目、分组、环境、状态筛选运行结果并查看失败证据 |
| 自然语言测试 | 用自然语言即时执行动作、断言、提取 | 快速探索页面并把有效指令保存为步骤 |
| 流程编排测试 | 维护独立自然语言流程 | 组合多步骤自然语言流程并执行 |
| 操作录制回放 | 录制、维护、回放用户操作路径 | 启动受控浏览器，自动采集点击、输入、跳转并转成用例 |
| 设置弹窗 | 配置主题、MidScene、浏览器 Runtime | 管理执行器、默认浏览器、主题外观 |

## 3. 核心对象与层级关系

### 3.1 项目 Project

项目是应用的顶层容器。一个项目代表一个被测网页应用或业务系统。

项目包含：

- 项目名称、说明、默认 URL。
- 多个环境，例如 Local、Staging、Production Mirror。
- 多个分组，作为项目内的二级维护维度。
- 多个测试用例。
- 多个录制资产。
- 多份需求文档。
- 多条登录凭据引用。
- 运行记录和运行分析。

UI 设计重点：

- 项目必须是全局上下文，用户需要随时知道当前正在操作哪个项目。
- 项目列表要支持下拉选择，也要支持列表浏览。
- 删除项目是高风险动作，需要明确确认。

### 3.2 分组 Group

分组是项目内的二级维度，用于按业务线、页面簇、模块或测试目标组织用例和录制资产。

已实现能力：

- 新建分组。
- 编辑分组名称和说明。
- 删除分组。
- 用例和录制资产可归属到分组。
- 删除分组时，相关用例和录制资产会迁移到可用兜底分组。

UI 设计重点：

- 分组不是筛选条件那么简单，而是可维护对象。
- 分组应在项目控制台、用例工作台、录制资产、运行记录中保持一致表达。

### 3.3 环境 Environment

环境用于描述被测应用的运行入口和浏览器参数。

环境字段：

- 环境名称。
- 环境类型：Local、Staging、Production Mirror。
- Base URL。
- Entry Path。
- 浏览器：Chromium、Firefox、WebKit。
- 视口：Desktop、Laptop、Mobile。
- Locale。
- Headless 开关。
- 绑定凭据。

UI 设计重点：

- 环境配置是测试运行前置条件，要有清晰的配置完整度表达。
- URL 和入口路径需要避免过长输入框造成视觉失衡。
- 环境会影响录制、回放、自然语言测试、运行记录筛选。

### 3.4 测试用例 Test Case

测试用例是项目内可执行的测试路径。它可以来自手工创建、自然语言、录制回放或 PRD 生成。

用例字段：

- 用例名称。
- 类型：场景、断言、提取、录制。
- 来源：手工、自然语言、录制、PRD。
- 所属分组。
- 默认环境。
- 目标 URL。
- 备注。
- 步骤列表。

步骤类型：

- 动作：自然语言操作页面。
- 断言：自然语言判断页面状态。
- 提取：自然语言提取页面信息。
- 录制回放：绑定一条录制资产并真实回放其中的步骤。
- 人工检查：记录需要人工确认的内容。

UI 设计重点：

- 用例编辑应突出“步骤编排器”的时间线结构。
- 普通自然语言步骤要轻量，避免过多边框。
- 录制回放步骤需要显示绑定的录制资产、步骤数量、归属分组和环境。
- 如果录制资产被删除，相关步骤会变成未绑定状态，UI 必须提示“需要重新绑定”。

### 3.5 录制资产 Recording Asset

录制资产是用户操作路径的可维护资产，可以来自真实浏览器录制、导入回放或 PRD 路径生成。

录制资产字段：

- 录制名称。
- 摘要。
- 来源：Live Recording、Imported Playback。
- 所属分组。
- 目标环境。
- 起始 URL。
- 回放对比目标。
- 标签。
- 步骤时间线。

录制步骤类型：

- 跳转。
- 点击。
- 输入。
- 等待。
- 核对。
- 快照。

真实录制已实现：

- 启动受控浏览器。
- 自动捕获页面跳转。
- 自动捕获点击。
- 自动捕获输入和选择。
- 保存 selector、value、pageUrl、capturedAt 等信息。
- 捕获快照并展示浏览器截图。

真实回放已实现：

- 录制回放步骤会真实执行 Playwright 动作。
- 回放期间关闭录制注入，避免回放动作污染当前录制资产。
- 每个回放节点会生成截图。
- 失败时记录失败原因并终止后续回放。

UI 设计重点：

- 录制资产库、受控浏览器、回放时间线、转译出口应形成清晰工作流。
- “启动录制器”和“捕获快照”是高频操作。
- 当前浏览器状态、当前 URL、截图预览要醒目但不喧宾夺主。
- 录制步骤需要看得出是用户真实路径，而不是普通文本列表。

### 3.6 需求文档 PRD Document

需求文档用于从产品需求生成测试路径草案。

已支持输入：

- 文本。
- Markdown。
- 文字型 PDF。

文档资产字段：

- 文档名称。
- 类型。
- 文件大小。
- 上传时间。
- 分析状态。
- 原始文本。
- 摘要。
- 覆盖域。
- 生成路径草案。

生成路径草案包含：

- 标题。
- 优先级：P0、P1、P2。
- 归属分组名称。
- 生成理由。
- 步骤列表。

已实现动作：

- 上传文件。
- 粘贴或编辑 PRD 文本。
- 分析并生成路径。
- 单条路径写入用例。
- 单条路径写入录制草稿。
- 全部写入用例。
- 展示覆盖矩阵和已写入状态。

UI 设计重点：

- PRD 文档分析页需要同时表达“输入、分析、覆盖、转化”四件事。
- 测试路径草案是设计重点，需清楚显示优先级、覆盖分组、写入状态和步骤摘要。
- “已覆盖”“已有录制”要明确区分，避免用户重复生成。

### 3.7 运行记录 Run Detail

运行记录沉淀每次测试执行结果，用于后续分析。

运行记录包含：

- 运行状态：running、passed、failed、neutral。
- 开始时间、结束时间、耗时。
- 运行摘要。
- 失败原因。
- 步骤日志。
- 截图、快照等产物。

已实现分析能力：

- 按项目过滤运行记录。
- 按分组、环境、状态筛选。
- 计算通过率。
- 展示总样本、失败数、运行中、健康判断。
- 聚合风险分组。
- 聚合风险环境。
- 展示最近失败原因。
- 展示单次运行步骤、截图、日志。

UI 设计重点：

- 这是统计页面，应尽可能一屏展示更多信息。
- 首页和运行记录页都需要高密度数据表达，但不要堆多层卡片。
- 失败原因、失败步骤、截图证据要比普通日志更突出。

## 4. 已实现的关键用户流程

### 4.1 从零开始创建测试空间

1. 用户进入首页。
2. 如果没有项目，系统引导创建项目。
3. 用户进入项目控制台，填写项目名称、默认 URL、说明。
4. 用户维护分组。
5. 用户维护环境和浏览器参数。
6. 用户保存登录凭据。
7. 用户进入用例、录制、PRD 或自然语言测试。

### 4.2 通过 PRD 生成测试路径

1. 用户进入需求文档分析页。
2. 上传 PDF、Markdown、文本，或直接粘贴 PRD 内容。
3. 系统提取文本并生成覆盖域和路径草案。
4. 用户查看每条路径的优先级、所属分组、生成理由和步骤。
5. 用户可以将路径写入正式用例。
6. 用户也可以将路径写入录制草稿，后续在录制页面继续维护。

### 4.3 录制真实用户操作并生成用例

1. 用户进入操作录制回放页。
2. 创建或选择录制资产。
3. 配置所属分组、目标环境、起始 URL、对比目标。
4. 启动受控浏览器。
5. 用户在浏览器中进行点击、输入、跳转。
6. 系统自动写入录制步骤。
7. 用户可补充等待、核对、快照等步骤。
8. 用户将录制资产写入测试用例。

### 4.4 执行录制回放用例

1. 用户进入用例工作台。
2. 选择分组和测试用例。
3. 添加或编辑“录制回放”步骤。
4. 为回放步骤绑定录制资产。
5. 点击执行用例。
6. 系统启动浏览器并真实回放录制步骤。
7. 每个回放节点生成截图和日志。
8. 执行完成后跳转到运行记录页查看分析。

### 4.5 使用自然语言探索并沉淀步骤

1. 用户进入自然语言测试页。
2. 选择动作、断言或提取模式。
3. 输入自然语言命令。
4. 选择目标环境。
5. 可开启 Deep Think 和 Deep Locate。
6. 启动会话并发送执行。
7. 系统返回对话式反馈。
8. 用户可将当前 prompt 保存为测试步骤。

### 4.6 查看测试结果和风险

1. 用户进入运行记录页。
2. 通过分组、环境、状态筛选运行样本。
3. 查看通过率、健康判断、风险分组、风险环境。
4. 选择单条运行记录。
5. 查看失败原因、步骤状态、截图和运行日志。

## 5. 浏览器与运行能力

当前应用是 Electron 桌面应用，已具备受控浏览器运行能力。

已实现能力：

- 启动 Playwright 浏览器会话。
- 支持 Chromium、Firefox、WebKit 配置。
- 支持 headless 和 visible 配置。
- 支持 locale 和 viewport 配置。
- 可导航到指定 URL。
- 可捕获页面截图。
- Playwright 不可用时生成可验证的占位快照。
- 录制模式下自动注入事件采集脚本。
- 测试运行模式下关闭录制注入，避免污染录制数据。

UI 设计重点：

- 浏览器区域是工作台核心，不应像普通表单附属区域。
- 浏览器状态需要包括 idle、starting、ready、navigating、closed、error。
- 浏览器截图既是操作反馈，也是测试证据。

## 6. 设置与主题

设置弹窗当前包含三类配置。

主题外观：

- 亮色。
- 暗色。
- 跟随系统。
- 默认亮色。

MidScene 配置：

- Endpoint。
- Workspace Name。
- Default Context。

Runtime 配置：

- Base URL。
- Browser。
- Viewport。
- Locale。
- Headless。

UI 设计重点：

- 设置是弹窗，但必须有明显的层级、遮罩和前景感。
- 输入框不宜过长，宽度应依据字段语义控制。
- 主题切换要影响全应用，不只是弹窗内部。
- 未完成 MidScene 基础配置时，自然语言、流程编排、录制回放入口会被引导到设置。

## 7. 首页工作台的设计目标

首页当前承担项目总览和快捷入口职责。

首页应表达：

- 当前项目。
- 项目健康度。
- 覆盖指数。
- 通过率。
- 失败数。
- 运行中数量。
- 分组、环境、用例、录制、文档等资产数量。
- 最近运行。
- PRD 解析、自然语言测试、录制回放等核心入口。
- 图表与表格巡检建议。

UI 设计重点：

- 首页是统计页面，应一屏展示较多信息。
- 应使用高密度但规整的信息排版。
- 不要让首页和其他页面风格割裂。
- 亮色主题应以白色为基础，暗色主题可采用科技工作台氛围。

## 8. 导航与全局交互

当前全局交互特征：

- 左侧主导航承载页面切换。
- Logo 和设置入口需要与普通菜单区分。
- 页面头部保持统一，但不应占用过多不可滚动空间。
- 内容区域负责滚动，头部区域不应随内容异常滚动或遮挡。
- 页面进入、内容加载、列表项出现已经具备动画优化基础。

UI 设计重点：

- 工作台要更像专业工具，而不是营销网站。
- 功能页面应尽量精简，避免多层卡片和过多边框。
- 统计页可以高密度，功能页要强调任务流和可操作性。
- 标题、间距、字号需要全局统一。

## 9. 重要状态与空态

UI 设计需要覆盖以下状态：

| 场景 | 状态 |
| --- | --- |
| 无项目 | 引导创建项目 |
| 无分组 | 创建项目时至少应有默认分组 |
| 无用例 | 引导新建用例或从 PRD/录制生成 |
| 无录制资产 | 引导创建录制或导入回放 |
| 录制资产无步骤 | 引导启动录制器或手动添加步骤 |
| 回放步骤无绑定录制 | 明确提示需要重新绑定 |
| 无 PRD 文档 | 引导上传或粘贴需求 |
| PRD 无路径草案 | 引导分析文档 |
| 无运行记录 | 引导执行用例 |
| MidScene 未配置 | 引导打开设置弹窗 |
| 浏览器启动失败 | 显示错误状态和失败消息 |
| Playwright 不可用 | 显示 stub 快照说明 |

## 10. UI 需要重点设计的模块

### 10.1 项目上下文切换

需要设计当前项目选择、项目摘要、项目状态的统一表达。项目切换影响所有页面，不应只在项目页可见。

### 10.2 分组二级维度

分组贯穿用例、录制和运行分析。UI 需要有稳定的分组标签、筛选和维护模式。

### 10.3 用例步骤时间线

步骤是核心资产。需要设计一种轻量但可扩展的时间线，能容纳自然语言步骤、录制回放步骤、人工检查步骤。

### 10.4 录制与浏览器舞台

受控浏览器、截图、URL、录制状态和步骤时间线需要组成一个完整操作台。

### 10.5 运行结果证据链

运行记录不只是列表，要表达“为什么失败、失败在哪、截图是什么、影响哪个分组/环境”。

### 10.6 PRD 到测试资产的转化

文档、覆盖域、路径草案、写入用例、写入录制之间需要形成可理解的转化路径。

## 11. 当前已实现但仍建议 UI 预留的能力

以下能力已有数据结构或初步入口，但 UI 可以预留更完整的设计空间：

- PRD 生成路径目前是基于文本分析的草案能力，未来会接入更强的 LLM 分析。
- 自然语言测试当前有会话、模式、增强选项和保存步骤入口，未来会有更完整的执行反馈和定位结果。
- 录制回放当前支持真实 click、input、navigate 等基础动作，未来需要更强的断言、等待策略和视觉对比。
- 运行记录当前支持截图、日志、失败原因，未来可扩展 trace、报告、趋势分析、 flaky 分析。
- 登录凭据当前是本机保存和引用，未来可能需要更完整的凭据绑定、脱敏和使用记录。

## 12. 设计交付建议

建议 UI 设计输出至少覆盖以下页面和状态：

1. 首页统计工作台：有项目、有运行数据。
2. 首页空项目态：引导创建项目。
3. 项目控制台：项目列表、项目配置、分组、环境、凭据。
4. PRD 分析页：文档库、导入区、覆盖矩阵、路径草案。
5. 用例工作台：分组列表、用例列表、步骤编排、录制绑定提示。
6. 录制回放页：录制资产库、浏览器截图舞台、录制时间线、转译出口。
7. 运行记录页：统计区、筛选条、运行列表、结果详情、失败截图。
8. 自然语言测试页：指令输入、模式切换、会话反馈、运行配置摘要。
9. 设置弹窗：主题、MidScene、Runtime，含未配置状态。

整体视觉方向建议：

- 默认亮色主题以白色为基础，保持清爽、专业、高信息密度。
- 暗色主题可强化科技工作台氛围，但不要牺牲可读性。
- 避免多层嵌套卡片，优先使用分区、间距、背景层次和轻量分隔。
- 表单页要克制，统计页要信息密度高。
- 所有页面标题、头部高度、操作区位置应统一。
